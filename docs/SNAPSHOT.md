# Five-year schema v2

## 무료 KV 운영 배포

R2 구독 없이 `RENT_SNAPSHOTS` KV를 사용합니다. 운영은 `RENT_QUERY_VERSION`으로 데이터 버전을 고정하고 `queries/{version}/regions/{gu}/{dong}.json` 및 `queries/{version}/comparison.json`만 읽습니다. 지역 객체는 최대 128 KiB, 비교는 최대 64 KiB이며 정상 요청당 1회 읽기입니다. 잘못된 동인지 판별할 때만 구 전체 객체를 추가로 한 번 읽습니다. 누락·검증 실패 시 전체 스냅샷 재집계로 되돌아가지 않습니다. 기존 완료 포인터·스냅샷 50개는 롤백용으로 유지합니다.

지역 객체는 `schemaVersion:1`, `datasetVersion`, `district`, `dong`, `meta`, `dongs`, 공통 `monthlySeries`, 5개 유형의 `summaries[{housingType,overview,yearly}]`를 저장합니다. 비교 객체는 같은 버전·기간의 125행을 저장합니다. 준비 도구는 내부 합계로 계산한 기존 응답과 일치하는지 대조하고 허용 필드만 저장합니다. 평균을 다시 평균내지 않으며, 공개 응답에 버전 고정용 내부 구조나 다른 유형의 선택 지표를 추가하지 않습니다.

새 자료는 새 버전으로 오프라인 준비하고 모든 객체를 해당 KV에 먼저 전송·검증한 후 코드의 버전 구성을 바꾸어 배포합니다. 같은 버전을 덮어쓰지 않아 전파 중 기존 배포의 기간이 섞이지 않습니다. KV를 브라우저에서 직접 조회하는 경로는 없습니다. 로컬 수집은 기존 R2 에뮬레이터를 사용하고, KV는 원격 수집의 쓰기 저장소로 사용하지 않습니다. Production/Preview KV는 분리합니다.

## 원본과 기간

`analysisStart=2022-01-01`, 종료일은 실행 시작 시 한국시간 전일로 고정(최대 2026-12-31). CSV는 파일명과 접수연도가 일치한다고 가정하지 않습니다. 확인된 파일 범위에 따라 2022 파일은 2022 계약을 소유하고, 2023 파일의 2022 계약은 제외합니다. API 접수연도 2024~2026의 계약은 전체 분석 기간에 배정합니다.

## 로컬 준비 산출물

`.generated/archives/manifest.json`은 실행 UUID, 분석 기간, 파일 SHA-256·행 수·인코딩·접수연도 범위·중복 범위 제외 건수와 25개 구를 기록합니다. 실행별 하위 디렉터리의 `{district}.json`은 `schemaVersion`, `district`, `fileYears`, `fileCounts`, `sourceFiles`, `accumulator`를 담습니다. 원본 행과 건물명·지번은 저장하지 않습니다.

누산기는 연도 비교용 `groups`와 모든 계약월의 `monthly`를 별도 키로 저장합니다. 각 그룹은 `transactionCount`, `sumDepositManwon`, `areaPriceCount`, `sumDepositPerM2Manwon`을 보존합니다. 소표본을 숨긴 후 평균끼리 병합하지 않습니다. `sourceRows = allIncludedCount + excludedCounts 합계`이고 연도 비교 거래 수와 월별 거래 수는 비교 기간 차이로 다를 수 있습니다.

## 관리자 프로토콜

`POST /api/admin/sync`, JSON body:

```json
{"action":"start","district":"11110","archive":"여기에 준비한 구별 JSON 객체","restart":false}
```

위 archive 문자열은 설명용이며 실제 요청은 객체를 전달합니다. 응답의 `jobId`로 `{"action":"step","district":"11110","jobId":"..."}`를 반복합니다. 상태만 조회하려면 `{"action":"status","district":"11110"}`입니다. 운영자는 `npm run sync` 도구를 사용하는 편이 안전합니다. 이 도구는 .env/서울 키를 읽지 않습니다.

## R2 내부 저장

- `jobs/{district}.json`: 작업 ID, 분석 기간, 출처 지문, 페이지 위치, 총건수·진행 건수·실제 호출 수, 누산기. 읽은 ETag를 조건으로 갱신합니다.
- `snapshots/{jobId}/{district}.json`: `schemaVersion:2`, `status:complete`, 기간, 시작/종료 시각, sourceRows/sourceCalls, 출처/중복 정책, 제외 건수, `groups`/`monthly`/`yearly`.
- `districts/{district}/latest.json`: 완료된 스냅샷 포인터. v1의 전역 latest.json은 읽지 않습니다.

단계는 `api → verify → 다음 연도 api → publish → publishing → complete`입니다. 한 번의 api/verify 단계는 최대 한 페이지(재시도 포함 최대 4회 외부 요청)를 처리합니다. 마지막에 검증된 집계만 저장합니다. `publish`에서 스냅샷을 저장하고 CAS로 `publishing`을 예약합니다. 이 단계의 재시작은 거부하며, 포인터와 완료 체크포인트를 마친 후에만 새 작업을 시작할 수 있습니다. 덕분에 재시작으로 무효화된 작업이 나중에 포인터를 바꿀 수 없습니다.

페이지 길이·예상 총건수가 달라지면 `failed`로 기록하고 기존 완료본은 보존합니다. 네트워크·인증 오류는 페이지 체크포인트를 진행시키지 않습니다. 같은 기간·파일 지문의 완료 작업은 재실행 시 재사용하고 `--restart`일 때만 새로 수집합니다. 수집 원본에 시점 고정 기능이 없어 같은 건수의 수정/재정렬까지 검증한다고 주장하지 않습니다.

## 공개 응답

`GET /api/summary?gu=11110&dong=all&type=all&comparison=samePeriod&view=dashboard`:

- `meta`: 스키마/스냅샷 버전, 실제 기간, 분석 연도 2022~2026, 파일 연도와 API 접수연도 구분, 수집 종료 시각, 원본 건수/호출 수, 사유별 제외 건수, 출처 처리 정책과 완전성 한계.
- `dongs[]`: 해당 자치구의 자료에 있는 법정동 `{code,name}` 목록. 주택유형 필터와 관계없이 유지하며 한글 이름순으로 정렬합니다.
- `overview`: 선택한 동·유형의 **전체 조회 기간** 거래 건수·면적 표본 수·두 평균·표본 신뢰 구분. 전체 월별 내부 합계와 건수로 정확히 계산합니다.
- `yearly[]`: 선택한 동·유형의 연도별 동일 기간 평균과 거래 건수. 내부 합계/건수로 계산하며 차트에 사용합니다. 작은 하위 그룹도 합산 후 최종 표본 수에 따라 평균을 숨깁니다.
- `monthlySeries[]`: 선택한 동 범위의 월·유형 합계 요약. 전체 유형과 4개 유형을 분리해 반환하며, 위 `type` 선택과 관계없이 함께 비교할 수 있습니다. 각 행은 `month`, `housingType`, `periodStart/End`, `transactionCount`, `areaPriceCount`, 두 평균, `reliability`, `isPartialMonth`입니다. 해당 월에 거래가 없으면 0건/평균 null, 10건 미만도 평균 null입니다. 분석 시작부터 종료 월까지 월을 빠짐없이 생성하며 마지막 부분월을 표시합니다. 브라우저가 동별 평균을 다시 평균내지 않습니다.

`dong`은 생략/`all`이면 전체 동, 지정하면 해당 자치구에 존재하는 5자리 코드여야 합니다. 자료에 없는 동은 HTTP 400이며, 존재하는 동과 유형의 조합에 거래가 없으면 HTTP 200, `overview.transactionCount=0`, 평균 null, `yearly=[]`입니다.

### 서울 전체와 두 지역 비교

`gu=all&dong=all`은 서울 25개 구의 완료된 같은 기간 자료를 내부에서 가산 합계로 병합합니다. 평균을 숨긴 개별 구·동의 소표본도 내부 합계로 포함한 뒤 최종 표본 수에 따라 평균을 표시합니다. 전체 기간·동일 기간 연도·모든 월/유형의 합계를 각각 계산하고, 구 평균의 단순평균은 사용하지 않습니다. `meta.scope=all`, `meta.districtCount=25`, `dongs=[]`, `overview`, `yearly`, `monthlySeries`만 반환하며 내부 그룹·합계는 노출하지 않습니다. 버전 고정 운영에서는 `view=dashboard`를 명시해야 합니다. 특정 동 코드를 붙이면 HTTP 400, 한 구라도 미준비 또는 기간 불일치이면 준비가 실패합니다. 이 합산은 오프라인 준비 및 로컬 레거시 조회에서 수행하고, 운영 조회는 준비된 작은 KV 객체 하나를 읽습니다.

두 지역은 공개 요약 경로를 각각 사용합니다. 화면의 `requestRegions`는 동일 조건을 중복 호출하지 않고 두 응답의 시작/종료일이 같은지 확인합니다. 한쪽 오류나 기간 불일치일 때 부분 결과로 비교하지 않습니다. 각 지역은 독립된 자치구·법정동 선택을 가지며 공통 주택유형으로 비교합니다. 평균과 거래 건수·연도별 값·월별 곡선은 A/B별로 유지합니다. 서울 전체와 포함된 구·동처럼 범위가 겹칠 수 있으므로 합산 건수를 만들지 않습니다. 동일 선택도 허용하되 안내하고, 평균 null인 지역이 있으면 평균 차이를 계산하지 않습니다.

기본 `view=all`의 다음 상세 항목은 기존 로컬 R2/레거시 분석 경로에서 유지합니다. 버전 고정 운영에서는 `view=dashboard`를 명시해야 하며 상세 요청은 HTTP 400입니다. 화면은 이미 dashboard만 요청합니다.

- `groups[]`: 선택한 법정동·유형·연도별 동일 기간 비교. 자치구·법정동 코드/명칭, 유형, 연도, 시작/종료일, 보증금/면적 각 표본 수, 두 평균, 신뢰 구분, 허용된 증감률.
- `monthly[]`: 선택한 법정동·유형·월별 요약. 과거 연도의 전체 월을 보존하고 현재 월을 부분월로 구분하므로 연도 비교와 기간이 다름.

출력하지 않는 항목: 원본 행·건물명·지번·보증금 합계 등 내부 누산값·파일 경로·서울 인증키·관리 토큰·원본 오류 메시지·임의 저장 필드. 각 표본 10건 미만은 해당 평균 null, 증감률은 양쪽 30건 이상일 때만 허용합니다. 비교 기간/연도·월·일자·자치구·유형이 일치하지 않으면 완료 상태라도 반환하지 않습니다.

### 자치구 비교

`GET /api/comparison?type=all`은 `type`만 허용합니다. `all`이면 전체 및 4개 유형의 25개 구 요약(125행), 특정 유형이면 25행을 반환합니다. 각 행은 자치구 코드/이름, 유형, 실제 시작/종료일, 거래 건수·면적 표본 수·두 평균·표본 신뢰 구분입니다. `meta`는 동일한 분석 시작/종료일, 선택 유형, 25개 구 수, 선택 유형의 거래 건수 합계를 제공하고 `districts`는 공식 구 목록입니다.

오프라인 준비 및 로컬 레거시 조회에서 내부 월별 가산 합계를 합쳐 계산합니다. 이때 포인터와 완료 스냅샷을 최대 동시 3개 구로 읽습니다. 운영 조회는 같은 계산으로 준비한 비교 KV 객체 하나를 읽습니다. 모든 구가 준비되고 기간이 일치해야 요약본을 생성합니다. 미준비·검증 실패는 `DATA_NOT_READY`(503)이며 0건으로 대체하거나 일부 구만 조용히 반환하지 않습니다. 추가 서울 API 호출·수집·R2 저장은 없습니다.

화면의 월별 관찰은 완결월·30건 이상 중 처음과 마지막 관측월의 차이를 계산하고, 자치구 관찰은 30건 이상 구의 최대·최소를 비교합니다. 표본 부족·부분월을 관찰에서 제외하고, 변화를 설명하는 원인을 추정하지 않습니다.
